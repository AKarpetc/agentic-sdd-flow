# ORD-44 — Paged order listing with validation

Add `GET /api/customers/{customerId}/orders?page=<n>&size=<m>` to Orders.Api.

Acceptance criteria:
1. `200 OK` with JSON `{"page": <int>, "size": <int>, "totalItems": <int>, "items": [{"id": <long>,
   "total": <decimal>, "status": "<name>"}]}`; items are the customer's orders (all statuses) ordered
   by `id` ascending; pages are 1-based and computed with the existing `PageMath.Skip` helper.
2. `page < 1`, `size < 1` or `size > 100` → `400 Bad Request` with a ProblemDetails body naming the
   offending parameter in `detail`.
3. A page past the end → `200` with an empty `items` array and the correct `totalItems`.
4. With the seeded data set: customer 1, page 1, size 2 → ids 101, 102 and `totalItems` 4; page 2 →
   103, 104; page 3 → empty; customer 2, page 1, size 10 → 201, 202; customer 99 → `totalItems` 0.
5. Unit tests cover paging arithmetic, the validation and an empty customer, and pass with `dotnet test`.
6. Commit messages are `ORD-44: <Description>`.
