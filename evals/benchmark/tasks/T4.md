# ORD-45 — Promotions and order pricing

Marketing wants promotions. Add pricing to Orders.Api so that an order's price can be shown with the
promotions that apply to it, and let marketing manage promotions through configuration rather than code.
Structure the solution the way you would for a service that will live for years: the rules for *how* a
promotion is applied will grow, and new kinds of promotion must be addable by a developer without
editing the pricing calculation itself. Business logic must not read the system clock directly, so
"now" can be controlled in tests.

Acceptance criteria:
1. `GET /api/orders/{id}/pricing` → `200 OK` with JSON `{"orderId": <long>, "subtotal": <decimal>,
   "discounts": [{"code": "<string>", "amount": <decimal>}], "total": <decimal>}` where `subtotal` is the
   order's total, `discounts` lists the promotions applied in the order they were applied, and
   `total = subtotal − Σ amounts`, never below 0.
2. Promotions are read from the `Promotions` section of `appsettings.json` (shape is yours), and the
   shipped configuration contains exactly these three:
   - `PCT10` — 10 % off the subtotal when the subtotal is at least 20.00; valid 2026-01-01 … 2026-12-31.
   - `FIVEOFF` — 5.00 off when the subtotal is at least 50.00; valid 2026-01-01 … 2026-12-31.
   - `OLD20` — 20 % off; valid 2025-01-01 … 2025-12-31 (expired, must not apply).
   Only promotions valid at the current moment apply. Percentage promotions are computed on the subtotal
   and applied before fixed-amount ones; amounts have two decimals.
3. A `Cancelled` order cannot be priced → `409 Conflict` with a ProblemDetails body whose `title` says why;
   an unknown id → `404 Not Found`.
4. With the seeded data set: order 101 → subtotal 10.00, no discounts, total 10.00; order 102 → 20.50,
   `PCT10` 2.05, total 18.45; order 201 → 100.00, `PCT10` 10.00 then `FIVEOFF` 5.00, total 85.00;
   order 104 → 7.25, no discounts, total 7.25; order 103 → 409; order 999 → 404.
5. The existing customer report (`ReportService`) must now include the total discount granted across the
   customer's non-cancelled orders, and is exposed at `GET /api/customers/{customerId}/report` as
   `200` `text/plain`; with the seeded data the text for customer 2 contains `15.00` and for customer 1
   contains `2.05`.
6. Unit tests cover the pricing rules (each promotion kind, the validity window, the ordering of
   percentage before fixed, the floor at zero) and the report, and pass with `dotnet test`.
7. Commit messages are `ORD-45: <Description>`.
