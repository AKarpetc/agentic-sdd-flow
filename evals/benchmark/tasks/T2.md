# ORD-43 — Cancel an order, with an outbox event

Add `POST /api/orders/{id}/cancel` to Orders.Api and an in-memory outbox.

Acceptance criteria:
1. An order in status `Placed` or `Paid` can be cancelled: `204 No Content`, and afterwards
   `GET /api/orders/{id}` reports `"status": "Cancelled"` (the change is persisted through
   `IOrderRepository.SaveAsync`).
2. An order in status `Shipped` or already `Cancelled` cannot: `409 Conflict` with a ProblemDetails body
   whose `title` explains why.
3. An unknown order id → `404 Not Found`.
4. `OrderService.CanCancelAsync` is the single source of the cancellation rule and is used by the new
   code; the rule is exactly "Placed or Paid".
5. Every successful cancellation appends an `OrderCancelled` event to an in-memory outbox, exposed at
   `GET /api/outbox` as `200` with a JSON array of `{"type": "OrderCancelled", "orderId": <long>}` in
   the order the cancellations happened (empty array when none).
6. With the seeded data set, in this sequence: cancel 101 → 204; cancel 102 → 204; cancel 104 → 409;
   cancel 103 → 409; cancel 999 → 404; `GET /api/outbox` → exactly two events, order ids 101 then 102.
7. Unit tests cover the rule (each status) and the outbox append, and pass with `dotnet test`.
8. Commit messages are `ORD-43: <Description>`.
